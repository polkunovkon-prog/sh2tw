# 08. Подсистема: честный ИИ — доктрины и GA (K5, K6)

## 8.1. Принцип «умнее, не богаче»

Усиление ИИ только тремя легальными рычагами: (1) **качество данных** — `.aic`-шаблоны замков, профили `gameRules` (на базе `gamerules_fixed.dat` из Lord Editor v1.4 — фиксы осад Короля/Ястреба и пехоты Быка, G5), хореография вторжений; (2) **стратегические решения** — agenda 07 §7.3; (3) **отбор** — GA подбирает параметры доктрин. Запрещено: стартовое золото/ресурсы ИИ сверх игрока, скрытые доходы, профили AI Overhaul, дающие ботам золото (G7 — авторы сами предупреждают; мы не используем вообще). Каждый матч — под протоколом 03 §3.9.

## 8.2. Ярус 1 — данные без кода (порядок работ этапа 5)

1. `gamerules_fixed.dat` → база (после V11 — совместимость с билдом заказчика).
2. 4–6 архетипов `.aic` (8.4) — переработка существующих 47 файлов игры (клонировать → править записи построек/приоритетов; семантика F5: план обязан содержать все военные постройки — нет казармы в плане = не построит; фермы/склады ИИ добавляет сам; приоритеты 1–255, меньше = раньше; выбор замка лорда из нескольких — случайный, лишние переименовывать).
3. Lord Editor v1.4 — росписи/веса/предпочтения (только честные поля: торговые веса, приоритеты найма, оборонительные группы; НЕ трогать стартовые ресурсы).
4. Хореография вторжений — шаблоны mission_events (волн, тайминги, отвлекающих манёвров) в DSL 05 §5.4.
5. DLL-уровень — только после 1–4 и только как цепочка (этап 4), точечные фиксы поведения с бэкапами.

## 8.5. Конвейер правки .aic

Прототипирование человеком в редакторе (Java AI Editor, stronghold-nation file 39) → экспорт → парсер 04 (`aic.py`) читает → генератор доктрин применяет геном (приоритеты записей, составы групп точек, флаги) → сборка (валидация длины 2928+8N) → установка: копия в `game_dir/aic/` с бэкапом оригинала (регламент 00 §0.7). Тест: игра с изменённым `.aic` — замок строится по плану (V12-подобный чек этапа 5).

## 8.6. Дифф-протокол 50 general values (ответ на вопрос 6 плана)

Семантика 50 общих значений `.aic` неизвестна (F4). Протокол разметки:

1. `aic_diff.py`: пары полных `.aic` (43 шт.) → таблица `general_values_matrix.csv`: файл × значение × позиция.
2. Кластеризация значений (k-групп); сопоставление с документированными характерами лордов (кто рашит/строит/стрелкует — статьи fandom/stronghold-nation) → гипотезы «значение N похоже на агрессию».
3. A/B в игре: базовый лорд → копия с одним изменённым значением → человек играет 10 минут, фиксирует отличие (форма отчёта — `experiments/reports/V8b.json`).
4. Результат — `ref/aic_general_values.md`: позиция → гипотеза → статус (подтверждено/не подтверждено/неизвестно). GA использует только подтверждённые.

## 8.7. GA-движок

```python
def run_ga(cfg):
    pop = [mutate(seed_doctrine, sigma=0.3) for _ in range(cfg.population)]
    hall_of_fame = []
    for gen in range(cfg.generations_max):
        results = evaluate_all(pop, cfg)          # параллельно, 8.9
        fitness = [fitness_of(r, cfg) for r in results]
        hall_of_fame.update(top(pop, fitness, n=10))
        log_generation(pop, fitness)
        if plateau(cfg): break
        elite = top(pop, fitness, n=cfg.elitism)
        pop = elite + [crossover(tournament(pop), tournament(pop))
                       for _ in range(cfg.population - cfg.elitism)]
        pop = [mutate(ind, cfg.mutation) for ind in pop]
    return validate_champion(hall_of_fame[0])      # 8.9: полный прогон + человек
```

Детали: ранговый отбор (устойчив к шуму фитнеса); скрещивание равномерное по генам; мутация гауссова `sigma = 0.15×диапазон`, вероятность на ген 0.3; элитизм 2; сиды в каждом прогоне записываются. Статистическая рамка: различение винрейтов 65 % против 50 % требует ~170 партий — GA работает на малых выборках шума (ранги), а финалисты прогоняются полноценно (по 20+ матчей) и валидируются живьём человеком.

## 8.8. Фитнес

```
F = 100 × Win − 0.5 × T_min − 30 × Losses_pct + 15 × Breakthrough_bonus
    − 20 × WallAbuse (штраф за «правильные» тактики, наоборот, бонус)
honesty_violations > 0  →  F = −∞ (матч в архив, доктрина в карантин)
```

Многокритериальность лексикографическая: честность → победы → время → потери. `Breakthrough_bonus` — премия за подтверждённый snapshot'ом прорыв стен/подавление обороны перед штурмом.

## 8.9. Стенд оценки

- **Портфель оборон:** 3–5 замков, построенных в редакторе заранее (сценарные пресеты, воспроизводимо; не «игрок без ввода»); против переобучения. Sanity-карты вне портфеля — для финалистов.
- **Исполнение матча:** кандидат = доктрина обороняющегося ИИ; атака — скриптованное Invasion (или лорд-ИИ по V1). Требования автоматизации: V1 (AI-only) + V2 (автозапуск) + V3 (детект) или мост Т1/Т2; не сошлось — полуавтомат: `ga_cli` ведёт человека (см. ниже).
- **Параллелизм:** 2–3 инстанса игры (Sandboxie-Plus, отдельные профили сейвов); watchdog: память > 1.6 ГБ или нет heartbeat 3 мин → рестарт инстанса, матч в `aborted`, не в зачёт; лимит машинного времени на поколение в `ga_config.yaml` (жёсткий).
- **Полуавтомат UX (ответ на вопрос 5):** вечером человек играет N матчей; `ga_cli next` показывает: карту, сторону, доктрину; после матча `ga_cli result` — форма из 3 полей (исход W/L, потери атакующего, потери обороняющего), Enter; всё в `match_result.json`. Три поля на матч, ≤ 60 секунд на ввод.

## 8.10. Приёмка этапов 5–6

- Этап 5: 4–6 архетипов установлены, живые тесты (замки строятся по плану, лорды воюют без залипания порога 200 золота — контроль казарм в плане); `gamerules_fixed` применён; протокол честности включён с первого матча; **бот выигрывает ≥ 30 % у человека при равных стартах** (окно 20 матчей) и исход объясним (замок/состав/тайминг).
- Этап 6: GA-прогон ≥ 10 поколений без нарушений честности; чемпион статистически значимо (биномиальный тест, α=0.1) лучше стартовой доктрины на портфеле; живая валидация человеком: 5 матчей чемпиона соответствуют ожиданиям; `champion.json` полный и воспроизводимый.
