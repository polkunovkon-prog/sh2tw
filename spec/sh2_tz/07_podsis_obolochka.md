# 07. Подсистема: оболочка кампании (K1)

## 7.1. Стек и общее устройство

FastAPI + uvicorn (localhost:8402), фронт — один `index.html` + `app.js` + `style.css` (ванильный JS, без сборщика), стиль «пергамент» (тёплый беж, тёмно-коричневый текст, красный акцент; ≤5 цветов). Состояние — `campaign_state.json` (03 §3.2); каждое действие атомарно: записать в `history/` → изменить состояние → дописать `events.jsonl`. Перезапуск сервера в любой момент не теряет ничего (богатство состояния — на диске).

```
sh2tw/shell/
  api.py            # REST-роуты (таблица 7.5)
  state.py          # загрузка/сохранение/undo, валидация переходов
  season.py         # цикл сезона (машина состояний)
  agenda_ai.py      # стратегический ИИ лордов
  autoresolve.py    # авто-резолв боёв
  events_catalog.py # события кампании
  diplomacy.py      # война/мир/союз/дань
  economy.py        # доходы, содержание, честь
  scene_client.py   # генерация scene_spec, вызов генератора/раннера (05)
```

## 7.2. Сезонный цикл (машина состояний)

```
[SEASON_START] → [EVENTS] → [AI_TURNS] → [PLAYER_ACTIONS] → [RESOLUTION] → [SEASON_END] → …
```

1. **SEASON_START:** доход (золото/честь по регионам), содержание армий, кулдауны, время года.
2. **EVENTS:** броски событий каталога 7.9 (RNG с записанным сидом — воспроизводимость).
3. **AI_TURNS:** каждый ИИ-лорд выполняет ≤1 кампанию (agenda 7.3); атаки на игрока → предложение боя (играть сценой или авто-резолв — выбор игрока; оборона своей земли всегда сцена по умолчанию, авто-резолв допустим).
4. **PLAYER_ACTIONS:** действия игрока до нажатия «Завершить сезон»: развивать регион (сцена театра — если кулдаун прошёл), набирать войска (без выхода в игру), купить деревню (100 чести, нативно — G1), двинуть армию, атаковать (сцена/авто-резолв), дипломатия.
5. **RESOLUTION:** применить итоги сцен/авто-резолвов; лояльность; проверить условия победы; счётчик пустых сезонов; переходы → P4.
6. **SEASON_END:** журнал, автосейв `history/state_<season>_end.json`.

Ограничение темпа: «правило руки» Castles II — за сезон не больше 1 военной кампании + 1–2 хозяйственных решения на сторону; «пустой» сезон (без решений игрока) ≤ 2 подряд (счётчик, предупреждение в UI).

## 7.3. Стратегический ИИ (agenda)

Не «разум», а приоритетная таблица — детерминированная по сиду, всякая решение логируется. Ежесезонно для каждого ИИ-лорда:

```
score(action) = w_aggr × threat_gain + w_greed × income_gain + w_build × dev_gain
                + w_loyal × coalition_bonus − risk × cost
```

| Действие | Условия | Эффект |
|---|---|---|
| `develop` | золото > резерв; castle_level < 5 | −золото, +development_points |
| `recruit` | угроза рядом или готовится атака | −золото, +roster (по таблицам найма региона) |
| `attack weakest neighbor` | армия ≥ 1.3 × гарнизон цели; мир не обязателен | сцена боя (если цель — игрок) / авто-резолв (ИИ-ИИ) |
| `defend` | на регион напали | гарнизон усиливается, лорд в замке |
| `buy village` | честь ≥ 100, есть нейтральная соседняя | −честь, +регион (нативно: покупка за честь — G1) |
| `offer peace / pay tribute` | проигрывает войну | предложение игроку (диалог) |
| `join coalition` | лидер (любой) ≥ 50 % регионов | против лидера (анти-снежный ком) |

Веса — из `persona` лорда (03 §3.1). ИИ-ИИ войны решаются авто-резолвом; результат виден в журнале (живость мира). Правило честности на стратегическом уровне: ИИ не получает доходов, которых нет у его регионов (тот же `economy.py`, что у игрока).

## 7.4. Авто-резолв

Формула v1 (калибруется на этапе 7, см. ниже):

```
S(сторона) = Σ_юнитов count × unit_value × (1 + 0.25 × vet)
att_eff = S_att × terrain_mod          # 0.8–1.2 по типу карты
def_eff = S_def × (1 + wall_bonus × castle_level) × terrain_mod
P(win_att) = 1 / (1 + exp(−k × (att_eff − def_eff) / max(att_eff, def_eff)))   # k=3.0
```

- `unit_value` — из `ref/unit_types.csv` (цена найма золотом+честью×вес; стартовые значения — Приложение D, финальные — замер в игре, задача S2.0).
- Потери: проигравший теряет 60–100 % (рулетка), победитель — `0.25 × (S_loser/S_winner)` юнито-стоимости, распределение по типам пропорционально составу; ветераны гибнут последними.
- **Калибровка (стратифицированная):** бины = {полевой/штурм} × {терцили соотношения сил}; минимум 5 реальных боёв на бин (набираются на этапах 5–7); критерий: |P_model − winrate_эмпир| ≤ 0.20 на бин и точность исхода на holdout ≥ 75 %. Не набралось данных — авто-резолв упрощается до «победа сильнейшего + потери по формуле» (пессимистичный fallback, журнал предупреждает).
- Штурмы: атака замка без осадных юнитов в росписи → штраф ×0.5 (стены); осадный парк (катапульты/башни/таран) даёт бонус ×(1+0.1×n) до ×1.5.

### REST API (все мутации идемпотентны по `request_id`; валидация переходов в `state.py`)

| `POST /api/region/{id}/develop` | начать сцену развития (проверка кулдауна театра) |

| `POST /api/region/{id}/buy` | купить деревню (честь) |
| `POST /api/battle/prepare` | собрать прогноз (без обязательств) |

## 7.6. Интеграция со сценами

`scene_client.py`: собрать `scene_spec` → вызвать генератор (CLI) → показать игроку инструкцию («Запускаю Stronghold 2 → карта S2TW_sc0042_siege») → опционально автозапуск → поллить раннер (`GET /api/scene/pending`) → принять результат (лестница детекта — 05 §5.7; ручной ввод — кнопки Win/Loss/Draw с автозаполнением из snapshot'а). Ожидание результата не блокирует UI (сезон «подвешен» в фазе RESOLUTION).

## 7.7. Правила применения итогов (балансные константы — `campaign_config`)

- Потери: выжившие = по snapshot; армия без снимка (авто-резолв/ручной) — по формуле 7.4.
- Ветераны: тип юнита, выживший в победном бою, получает `vet += 0.5` (потолок 1.0); ветеран ×1.25 к unit_value в авто-резолве и к казначейской стоимости в провижининге C.
- Захват региона: убийство лорда-владельца в сцене → `TakeEnemyCastle`-цепочка; регион победителю, застройка −1 уровень (разграбление), лояльность 30 (восстание при <25 — событие 7.9).
- Милосердие: `aborted` (краш/выход) — армия игрока сохраняется, сезон откатывается к началу действия; таймер реального времени сцены фиксируется (анти-эксплойт: 3 aborted подряд → событие «дезертирство» −20 % армии).
- Смерть лорда-ИИ: его регионы переходят убийце (нативная механика смерти лорда — G1); лорд-человек погиб в обороне → поражение кампании (или «наследник» — настройка сложности, по умолчанию поражение).

## 7.8. Дипломатия

Состояния пар: `war | peace | alliance`; дань (`tributes`); союзники ИИ вступают в войну через 1 сезон после запроса; нативное `SetAllies` проставляется генератором в сценах с >2 сторонами. Мир оплачивается данью или честью. Никаких «сложных» механик (non-goal).

## 7.9. Каталог событий (анти-снежный ком и живость)

Реестр в `events_catalog.py`; каждое: условие, вероятность/сезон, эффект, запись в журнал. Стартовый набор (расширяемый): неурожай/эпидемия/крысы (нативные бедствия переносятся в кампанию штрафом дохода); ярмарка (+честь); наёмники предлагают роспись со скидкой; восстание в свежем завоевании (лояльность <25 → армия бунтовщиков, сцена подавления); коалиция против лидера (флаг); суровая зима (содержание ×2); посольство (дань/честь); охота (честь); свадьба/пир (+честь, −золото). Вероятности — константами в `campaign_config` (`events` блок, добавляется при этапа 8), анти-снежный ком: `coalition` и `rebellion` — обязательные.

## 7.10. Экономика

Доход региона = `base_income + product_bonus + деревни(50 з/мес нативно — G1) − содержание гарнизона`; честь = пиры/церкви/события (нативный генератор — через сцены; в оболочке — только события). Всё сведено в `economy.py`, один и тот же код для игрока и ИИ (честность стратегического уровня).

## 7.11. Сохранение/undo/журнал

Автосейв на SEASON_END; undo — откат к последнему `history/` слепку (максимум 3 шага, дальше — загрузка слепка); полный журнал `events.jsonl` + человекочитаемый журнал сезона на экране 1. Сейв-скам отслеживается метрикой (11): перезагрузка перед боем >1 на 3 боя → предупреждение, >3 → событие «проклятие трусости» (−честь; решение человека, включается флагом).

## 7.12. Приёмка (машинное + живое)

- Юнит: все переходы сезона покрыты тестами (фикстуры состояний); RNG-детерминизм (сид) — прогон дважды, идентичные журналы.
- API: контракты 7.5 — integration-тесты FastAPI (`TestClient`).
- UI: скриншот-тесты 4 экранов (chromedriver/playwright локально) — отсутствие пустых зон, все кнопки кликабельны.
- Живое (этап 7): 3 полных сезона с ≥2 реальными сценами; ≤15 переходов соблюдено; состояние не рассинхронизировалось (сверка `events.jsonl` с UI-журналом); авто-резолв дал прогнозы в пределах калибровки.
