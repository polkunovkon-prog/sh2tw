# 09. Этапы 0–8: задачи, критерии, оценки

Оценки — «вечера» по 2–3 часа; «маш-ч» = машинные часы без человека. Поправка на исполнителя Qwen-8B-IQ3_S (медленнее итерации, больше правок по ревью) уже учтена (обоснование пересмотра — файл 12, вопрос 9). Каждый этап заканчивается играбельным/проверяемым артефактом (P5). Ключевые задачи продублированы машинно в `task_registry.json` — он источник статусов; этот файл — источник содержания.

## Этап 0 — бумажный прототип петли (1–3 вечера + 1 игровой вечер)

Цель: проверить, что петля «сезон → решение → бой → итог» затягивает ДО написания кода. Инструменты: Google Sheets/бумага, готовые карты копии (Strong and Stable, Two Pronged Crown, Whitebear), бои руками.

Задачи: 0.1 — таблица: 8 регионов, 4 лорда, доходы, росписи, дипломатия; 0.2 — правила сезонного цикла (черновик 07 §7.2); 0.3 — 3–5 боёв на готовых картах, старт/итоги руками; 0.4 — протокол впечатлений (форма: что бесит / чего не хватает / что затянуло).

**Приёмка:** сыграно ≥ 5 сезонов и ≥ 3 боя; заполнен протокол впечатлений; список правок дизайна §4 плана. **Стоп-условие:** не затянуло → проект остановлен с экономией месяцев (это успех этапа, а не провал).

## Этап 1 — верификационные эксперименты (2–4 игровые сессии + 1–2 вечера агента)

Полные протоколы — файл 10. Человек исполняет V1–V6, V5b; агент готовит формы отчётов, разбирает результаты (sejвы, CRC), фиксирует решения. Задачи агента: 1.1 — `tools/check_build.py` (CRC exe против эталона v1.5.0, отчёт V5); 1.2 — скрипт слежения Saves/ для V3 (лог файл-событий); 1.3 — разбор результатов V1–V6 в `experiments/reports/`; 1.4 — сводный `report_v.json` + решение по треку 2 (человек утверждает).

**Приёмка:** каждый V закрыт отчётом; в `report_v.json` — решения: трек 2 (да/нет), канал детекта исхода (лестница), подтверждённые каналы провижининга (V7), судьба rehost (V4), лимит лордов театра (V6). **Стоп-условия:** V4 провал → обороны на шаблонах уровней; V5 провал → трек 2 закрыт, трек 1 не страдает.

## Этап 2 — парсер (4–7 вечеров)

Задачи (каждая — микрозадача с тестом):
- S2.0 `ref/unit_types.csv` + `ref/buildings.csv` (из доков OpenSH2 + замеров в игре; цены юнитов — Приложение D).
- S2.1 `s2m_file.py`: заголовок + сегменты + zlib + round-trip.
- S2.2 `object_tree.py`: обход по маркерам + raw-объекты.
- S2.3 корпус-тест: 89 карт + 78 сейвов round-trip.
- S2.4 `map_header.py`: EstateMarkers, Scenario, Mission, EstateStartupTroopPlacement (по докам + hexdiff).
- S2.5 `entities_decode.py` + `s2game.py` (высоты — raw, объекты — по реестру).
- S2.6 `snapshot_builder.py` + CLI `parse`.
- S2.7 `diff_engine.py` + CLI `diff`.
- S2.8 `honesty/accounting.py` + CLI `honesty`.
- S2.9 `aic.py` + `gamerules.py` (round-trip на 47 .aic и gamerules_fixed.dat).

**Приёмка:** критерии 04 §4.7 (все 4 пункта). **Стоп-условие:** спорные объекты остаются raw — этого достаточно; непарсируемый сегмент — только raw-копия.

## Этап 3 — генератор сцен (6–12 вечеров)

- S3.0 каталог карт-заготовок (`catalog-maps`) + отбор 6–10 шаблонов (человек утверждает роли).
- S3.1 человек расставляет маркеры вторжений на шаблонах в редакторе; агент фиксирует эталоны + хэши.
- S3.2 `patcher.py` + DSL манифестов + `diff-maps` CLI (процедура 05 §5.3).
- S3.3 патч-библиотека: старт-ресурсы, стартовые войска (по V7), таймеры (5–8 патчей на шаблон).
- S3.4 `event_dsl.py`: компилятор mission_events → ScenarioEvent (golden-тесты пар «spec→байты»).
- S3.5 `mapheader_writer.py` (L2) + эталонная планка round-trip на 5 ванильных картах.
- S3.6 `rehost.py` (по V4) + сборка оборонительной сцены из снимка.
- S3.7 `runner/` (launcher, watcher, outcome-лестница, watchdog).
- S3.8 сквозной тест: 4 типа сцен собираются, грузятся в игре (V12).

**Приёмка:** критерии 05 §5.9; человек подтверждал живьём загрузку каждой из 4 сцен. **Стоп-условие:** писатель капризничает на конкретных полях → патчер + заготовки (закрывает ~90 % сценариев); rehost недоступен → шаблоны уровней.

## Этап 4 — d3d9-мост (4–8 вечеров; только при успехе V5)

Задачи: S4.1 изучение docs/ unofficial-patch + каркас прокси; S4.2 heartbeat (Т4); S4.3 save_now (Т2); S4.4 outcome (Т1); S4.5 автозагрузка (Т3, связка с V2); S4.6 install/remove-скрипты + чек-лист V12b. **Приёмка:** все Т1–Т4 на живой игре, чистый откат, ни одного краша за 30-минутный прогон. **Стоп-условие:** любые непонятные краши → мост заморожен, система на треке 1.

- S5.7 честность с первого матча + окно 20 матчей с человеком (приёмка 30 %).

**Приёмка:** 08 §8.10 (этап 5). **Стоп-условие:** архетип ломает строительство → откат к клону ванильного `.aic` этого лорда; разбор в QUESTIONS.

## Этап 6 — GA-конвейер (5–10 вечеров + 10–40 маш-ч)

## Порядок и параллелизм

Линейная зависимость: 0 → 1 → 2 → 3 → (5 → 6) → 7 → 8. Этап 4 параллелен 5–6 (другой исполнительский профиль — C++). Этап 5 частично параллелен 3 (архетипы не зависят от писателя). Правило: не начинать следующий этап без играбельного результата текущего (P5) — исключение: задачи S2.0/S5.1 можно готовить параллельно этапу 1.
