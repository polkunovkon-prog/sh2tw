# 06. Подсистема: d3d9-мост (трек 2, K7 — опциональный)

## 6.1. Статус и предусловия

Мост — **ускоритель, не зависимость**: вся система обязана работать без него (P2). Включение этапа 4 возможно только при: (a) успех V5 (CRC `Stronghold2.exe` репака совпадает со Steam v1.5.0); (b) успешной установке sh2-unofficial-patch v0.9.0 (Unlicense, коммит 22.11.2026) на копию заказа; (c) согласии человека. Если билд репака отличается — трек 2 закрыт до покупки Steam-копии (решение плана, риск-реестр 11).

## 6.2. Что делает мост

| Функция | Механизм | Ценность |
|---|---|---|
| Т1. Телеметрия исхода | перехват вызова игрового экрана победы/поражения (адреса — из docs/ unofficial-patch, сверить по их `docs/architecture.md`) | детект исхода без парсинга сейвов |
| Т2. Программный автосейв | вызов внутренней SaveGame (unofficial-patch уже работает с сохранением: «save engine working» — README v0.9.0) по командному файлу | снапшот ровно в момент события |
| Т3. Автозагрузка сцены | перехват меню / передача имени карты при старте | GA без ручного клика (в связке с V2) |
| Т4. Heartbeat | пишет `%TEMP%/sh2tw_bridge/heartbeat.json` (FPS, память, игровое время) 1 раз/5 с | мониторинг GA-прогонов, детект зависаний |

## 6.3. Архитектура: цепочка, не конкуренция

Две прокси-d3d9 конфликтуют (G7) — поэтому мост встаёт **цепочкой поверх** unofficial-patch через официальный механизм `d3d9_chain.dll` (документ: `docs/features/dll-chaining.md` sh2-unofficial-patch):

```
Stronghold2.exe → наш d3d9.dll (прокси)
                    ├─ пересылает вызовы → d3d9_chain.dll (unofficial-patch) → система d3d9
                    └─ свои детуры (только Т1–Т4) на адресах, НЕ занятых unofficial-patch
```

Порядок сборки: (1) изучить `docs/architecture.md` unofficial-patch (детуры 5 байт, GetModuleHandleA); (2) взять их паттерн прокси; (3) свои хуки — только на функции, не перекрытые патчем (сверка списков RVA при инициализации: если адрес занят — функция моста отключается, лог в heartbeat, остальное работает).

## 6.4. IPC-протокол (файловый, без сокетов)

Каталог `%TEMP%/sh2tw_bridge/`:

| Файл | Кто пишет | Содержимое |
|---|---|---|
| `heartbeat.json` | мост, каждые 5 с | `{"ts":…, "pid":…, "fps":…, "mem_mb":…, "game_months":…, "scene_tag":…}` |
| `outcome.json` | мост, однократно | `{"scene_tag":…, "outcome":"win|loss", "ts":…, "save":"имя автосейва"}` |
| `command.json` | оболочка | `{"cmd":"save_now"|"quit_after_save", "tag":…}` (мост удаляет после исполнения) |
| `bridge.log` | мост | append-only события инициализации/ошибок |

Правила: запись атомарная (tmp+rename); формат JSONUTF-8; при падении разбора — игнор, не краш игры.

## 6.5. Скелет и сборка

C++ (MSVC 2019 v142, x86, `/MT`), один `bridge.cpp` + `dllmain.cpp` + `json.hpp` (single-header nlohmann). Не более 1500 строк суммарно; никакой сторонней логики. Сборка: скрипт `build.bat` (msbuild) + артефакт `sh2tw_bridge.dll`. Тесты: ручной чек-лист V12b (установка → heartbeat появился → команда save_now создаёт сейв → исход пишется → игра стабильна 30 мин → удаление чистое).

## 6.6. Безопасность и откат

- Установка/удаление только скриптами `tools/bridge/install_bridge.py` / `remove_bridge.py`: копия dll в `game_dir`, бэкап-реестр файлов, `--dry-run`, журнал.
- Версионный рукопожатие: при старте мост сверяет CRC exe с зашитым; не совпал — мост полностью пассивен (только пересылка вызовов), в heartbeat — предупреждение.
- Kill-switch: переименование/удаление одного `sh2tw_bridge.dll` возвращает игру к состоянию «unofficial-patch only».
- Память игры не пишется нигде, кроме документированных точек хуков; никакой модификации логики ИИ на уровне кода (принцип «ИИ в данных» — P1/P3).
